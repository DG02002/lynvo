<DocSection id="authentication">

Bearer authentication protects the Plugin Server endpoints that Lynvo calls. One Plugin Server API key authenticates every request Lynvo sends to `/verify`, `/usage`, `/extract`, and `/discover`.

The generated starter validates the `Authorization: Bearer` header through `validateBearerCredential` from the protocol package, which compares the presented key against the configured key in constant time. To generate a random 32-byte key, run:

<CodeBlock label="Terminal">

```sh
openssl rand -base64 32
```

</CodeBlock>

Use the same value in your Plugin Server environment and in Lynvo when you [connect the server](/developer/connect).

To configure the key for local development, set it in `.dev.vars`:

<CodeBlock label=".dev.vars">

```dotenv
LYNVO_PLUGIN_SERVER_API_KEY=YOUR_LOCAL_PLUGIN_SERVER_API_KEY
```

</CodeBlock>

Keep `.dev.vars` out of version control; the template already ignores it. To configure the production key as a Cloudflare secret, run:

<CodeBlock label="Terminal">

```sh
pnpm wrangler secret put LYNVO_PLUGIN_SERVER_API_KEY
```

</CodeBlock>

Never place the key in a manifest, URL, response body, browser bundle, or log. A rejected key produces an `AUTH_INVALID` error with HTTP status 401:

<CodeBlock label="401 response">

```json
{
  "ok": false,
  "error": {
    "code": "AUTH_INVALID",
    "message": "API key was rejected."
  },
  "extensions": {}
}
```

</CodeBlock>

If you replace the generated route layer, authenticate protected requests before reserving usage or sending upstream requests.

</DocSection>
