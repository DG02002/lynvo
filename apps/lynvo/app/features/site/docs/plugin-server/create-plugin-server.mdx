The creator package generates a standalone Plugin Server project backed by a Cloudflare Worker. Complete the [development prerequisites](/developer/prerequisites) first; the generator does not require a clone of the Lynvo repository.

To generate the project, run the creator from the directory where you want the project to live:

<CodeBlock label="Terminal">

```sh
pnpm create lynvo-plugin-server@latest my-lynvo-plugin-server
cd my-lynvo-plugin-server
cp .dev.vars.example .dev.vars
pnpm check
pnpm test
pnpm build
```

</CodeBlock>

`pnpm check` type-checks the project, `pnpm test` runs the contract tests, and `pnpm build` optimizes Plugin icons and bundles the Worker with a Wrangler dry run. None of them require a live Cloudflare Worker.

Set `LYNVO_PLUGIN_SERVER_API_KEY` in `.dev.vars`, then run `pnpm dev` to start the local Worker. The generator installs dependencies for you; if you pass `--skip-install`, run `pnpm install` before the checks.

## What the generator creates

- `src/index.ts` with the manifest, shared runtime, and Hono routes
- `src/plugins/example.ts` with a deterministic example Source adapter
- `scripts/optimize-images.mjs` for Plugin icons in `public/icons/sources/`
- `tests/contract.test.ts` with the first contract checks
- `wrangler.jsonc`, `.dev.vars.example`, `tsconfig.json`, and `vitest.config.ts`
- `package.json` with a semver dependency on `@dg02002/lynvo-plugin-server-protocol`
- A `README.md`, an MIT `LICENSE`, and a `.gitignore`

To make the project yours, edit these files first:

1. Replace the example matcher and Plugin metadata in `src/index.ts`
2. Replace the example Source adapter in `src/plugins/example.ts`
3. Add Source fixtures to `tests/contract.test.ts`

The starter includes five contract checks: a valid manifest, rejected invalid bearer credentials, finite usage, a valid Extraction envelope, and the error for opaque resource-ID targets. See [testing](/developer/testing) for the full list the suite should grow to cover.

The starter's usage response is a finite test fixture so the checks run without a database. Replace it with durable accounting before production deployment, and use `pnpm deploy` only after the contract checks pass and the production secret is configured.

The generated project has no workspace or local-link dependency, so you can copy it to another repository without cloning Lynvo.
