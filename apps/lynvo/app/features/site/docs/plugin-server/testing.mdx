<DocSection id="testing">

The generated checks prove the protocol contract — types, endpoint behavior, and the Wrangler bundle — without a live Cloudflare Worker. Run them after implementing the Plugin and before deploying the Worker.

To run the local checks, use:

<CodeBlock label="Terminal">

```sh
pnpm check
pnpm test
pnpm build
```

</CodeBlock>

To start the Worker, run `pnpm dev` in a separate terminal. The local Worker serves `http://localhost:8787`.

## Exercise the endpoints with curl

To inspect the public manifest, call:

<CodeBlock label="Terminal">

```sh
curl http://localhost:8787/manifest
```

</CodeBlock>

To verify the local bearer key, call:

<CodeBlock label="Terminal">

```sh
curl -X POST http://localhost:8787/verify \
  -H "Authorization: Bearer YOUR_LOCAL_PLUGIN_SERVER_API_KEY"
```

</CodeBlock>

Lynvo also reads usage when it connects a server, so confirm the usage response passes the same validation:

<CodeBlock label="Terminal">

```sh
curl http://localhost:8787/usage \
  -H "Authorization: Bearer YOUR_LOCAL_PLUGIN_SERVER_API_KEY"
```

</CodeBlock>

To test a Source Extraction, send a request like:

<CodeBlock label="Terminal">

```sh
curl -X POST http://localhost:8787/extract \
  -H "Authorization: Bearer YOUR_LOCAL_PLUGIN_SERVER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "input": {
      "kind": "source",
      "sourceUrl": "https://media.example.com/watch/123"
    }
  }'
```

</CodeBlock>

## Local origins and tunnels

Use `http://localhost:8787` when Lynvo and the Plugin Server run on the same machine. Lynvo accepts local HTTP only when the hostname is exactly `localhost`; loopback IP addresses such as `127.0.0.1`, LAN addresses, and every other host must use HTTPS.

To test against a remotely hosted Lynvo instance, expose the local Worker through an HTTPS tunnel. Wrangler's interactive development server starts one with the `t` shortcut. To verify the public origin before connecting it, call:

<CodeBlock label="Terminal">

```sh
curl https://<your-tunnel-hostname>/manifest
```

</CodeBlock>

The response must succeed, and every absolute manifest URL, including Plugin icon URLs, must use the public HTTPS origin. A tunnel commonly terminates TLS before forwarding HTTP to the Worker: if the manifest generates absolute URLs from the request, honor `X-Forwarded-Proto: https` or configure the public origin explicitly. Never hardcode a temporary tunnel hostname.

## Grow the contract suite

The starter's five checks cover a valid manifest, rejected invalid bearer credentials, finite usage, a valid Extraction envelope, and the error for opaque resource-ID targets. Extend `tests/contract.test.ts` as you add Source behavior, and cover:

- Valid and invalid manifest metadata
- Missing, invalid, and valid bearer credentials
- Finite usage responses and unique metric IDs
- Supported and unsupported Source URLs
- Playable item, folder, group, and unresolved item nodes
- Unresolved item follow-up through the same Plugin Server
- Password-required and invalid-password flows
- Malformed JSON and invalid request shapes
- Exhausted usage before upstream work starts
- Safe temporary and permanent failure responses

Add Source fixtures before you deploy a real Source implementation, then continue with [deployment](/developer/deployment) and [connecting the server to Lynvo](/developer/connect).
