<DocSection id="request-schema">

`POST /extract` accepts a Source URL or the Node identity of a previously emitted unresolved item, and returns Media Nodes. The shared runtime validates the request before your Plugin runs; a body that fails validation never reaches Source code.

The request envelope supports these fields:

| Name        | Type   | Required | Description                                                                                                         |
| ----------- | ------ | -------- | ------------------------------------------------------------------------------------------------------------------- |
| `input`     | object | Yes      | A `source` input or a `node` input; see below                                                                       |
| `pluginId`  | string | No       | Selects a specific Plugin from the manifest catalog                                                                 |
| `password`  | string | No       | Content password for the Source; attempt-scoped, never persisted by Lynvo                                           |
| `basicAuth` | object | No       | `{ "username", "password" }` for source-side HTTP Basic Auth; sent only when the manifest sets `features.basicAuth` |
| `proxy`     | object | No       | `{ "provider", "token" }` carrying the user's own proxy token for this request's upstream calls                     |

A `source` input carries one field, `sourceUrl`. A `node` input carries `nodeUrl`, `resourceId`, or both; a node input with neither fails with the schema message `Node requires nodeUrl or resourceId`.

To request the first Extraction of a Source URL, send a `source` input:

<CodeBlock label="POST /extract">

```json
{
  "input": {
    "kind": "source",
    "sourceUrl": "https://media.example.com/watch/123"
  }
}
```

</CodeBlock>

To follow up on an unresolved item, send the Node identity returned by the same Plugin Server:

<CodeBlock label="POST /extract">

```json
{
  "pluginId": "example-media",
  "input": {
    "kind": "node",
    "nodeUrl": "https://media.example.com/folders/bonus",
    "resourceId": "bonus_v1"
  }
}
```

</CodeBlock>

The protocol package also exports `createSourceExtractRequest` and `createNodeExtractRequest` helpers that build these envelopes with the optional fields.

## Credentials on an Extraction request

Two separate credentials can ride an Extraction request, and they authenticate different hops. The Plugin Server bearer key in the `Authorization` header authenticates Lynvo to the Plugin Server. The `basicAuth` and `password` fields authenticate the Plugin Server to the Source.

Lynvo removes URL userinfo before forwarding a target and does not send the original top-level Source URL on unresolved item follow-up requests. A `proxy` token must be used for that request's upstream proxy calls instead of the server's shared proxy credits, and must never be logged.
