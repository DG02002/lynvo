<DocSection id="what-is-a-plugin-server">

A Plugin Server is a deployed service that runs one or more Plugins and follows the Plugin Server Protocol. Lynvo never talks to a Source directly — it hands the server a Source URL or an unresolved item and renders the Media Nodes that come back over HTTPS and JSON.

Splitting the work this way keeps every Source integration on the same contract. The Plugin Server owns:

- The public manifest at `GET /manifest`
- Bearer authentication for protected endpoints
- Routing each request to the matching Plugin
- Request and response validation
- Finite usage limits and their enforcement
- Protocol error responses
- Deployment, logs, and operational status

Lynvo owns everything product-side: registering the Plugin Server, selecting it for matching URLs, saving extracted nodes, tracking opened markers and selected links, and handing the final URL to an external Android player. The split is strict — an opened marker records only that an item was opened, and neither side stores a playback position or resume state.

## Lynvo Plugin Servers and Custom Plugin Servers

Lynvo talks to two kinds of Plugin Server, and they differ only in who operates them. The Lynvo Plugin Server is the server Lynvo runs for its own Plugins. A Custom Plugin Server is one you connect and manage yourself — generated from the starter project, deployed to your own origin, and registered in [Settings](/settings/plugins).

One Plugin Server can host one Plugin or several. Deploy and connect the server once, then publish each Plugin in its manifest.

<DocsNote title="Direct Media">

Direct Media is a first-party Plugin hosted on the Lynvo Plugin Server. Lynvo asks the Plugin whether it can handle a link after checking the domains configured for it.

</DocsNote>
