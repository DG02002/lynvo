<DocSection id="what-is-a-plugin-server">

A Plugin Server is a deployed service that runs one or more Plugins and follows the Plugin Server Protocol. Lynvo sends it a Source URL or an unresolved item, and the server responds with normalized Media Nodes over HTTPS and JSON.

The Plugin Server owns the work shared by every Source integration:

- The public manifest at `GET /manifest`
- Bearer authentication for protected endpoints
- Routing each request to the matching Plugin
- Request and response validation
- Finite usage limits and their enforcement
- Protocol error responses
- Deployment, logs, and operational status

Lynvo owns the product behavior around that service. It registers the Plugin Server, selects it for matching URLs, saves extracted nodes, tracks opened markers and selected links, and hands the final URL to an external Android player. An opened marker records only that an item was opened. Neither Lynvo nor the Plugin Server stores a playback position or resume state.

## Managed and Custom Plugin Servers

Lynvo talks to two kinds of Plugin Server. The Lynvo Plugin Server is the server Lynvo operates for its own Plugins. A Custom Plugin Server is one you connect and manage yourself — built from the generated project, deployed to your own origin, and registered in [Settings](/settings/plugins).

One Plugin Server can host one Plugin or several. Deploy and connect the server once, then publish each Plugin in its manifest.

<DocsNote title="Direct Media">

Direct Media is a first-party Plugin hosted on the Lynvo Plugin Server. Lynvo asks the Plugin whether it can handle a link after checking the domains configured for it.

</DocsNote>
